# Skill routing
Use matching Skills and required references, not an arbitrary numerical cap or S-level ban.
- feature-discovery: consequential ambiguity; evidence first, reversible assumptions continue.
- feature-development: normal backend/frontend/full-stack functionality, including existing admin forms/buttons.
- code-audit-fix: symptoms and code/environment/config/upstream diagnosis.
- acceptance-verify: user outcomes across UI/API/integration, beyond unit-test success.
- release-deploy: one authorized release lifecycle using project profile and existing inspection/database/checklists.
- impeccable: requested incumbent visual/UX refinement; preserve design language unless redesign requested.
- design-taste-frontend OR frontend-design: brand/landing/portfolio visual work. One primary aesthetic authority, not three conflicting stacks.
- architecture-refactor: analysis read-only; authorized staged implementation continues without another GO.
- lab-ai-delivery: S4 or explicit formal work, not every multi-file fix.

Existing useful scripts/resources remain. No harness-upgrade Skill; the Human initiates model adaptation. Skills live in discoverable global directories, not a conflicting duplicate tree here. New sessions may be needed for discovery. Project migration does not distribute global Skills across machines.
