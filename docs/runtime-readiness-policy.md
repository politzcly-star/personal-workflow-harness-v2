# Runtime readiness and protected execution
Installation, configuration validity and LIVE capability are separate facts. At adoption/client/provider change, run scripts/runtime-inspect.py for a redacted local inventory. It reads no auth/global config/transcripts and makes no API/network/model calls. Check actual exposed runtime metadata for delegation, role selection, hooks, effective context window/threshold and approval transport; leave inaccessible facts unverified. Repeat only when relevant runtime conditions change. Missing optional capabilities must not block unrelated local work.
The current root/model is selected by Human/platform. Role files are candidates, not proof any tool consumes them. Use supported role/model arguments within selection permission or honestly record inherited/unverified behavior. Do not ask a model its name as a test. Live smoke probes use only already-authorized normal work; no paid model-selection experiment by default.
Protected local-test, remote-diagnostic and release operations still need actual scope/authority. A test-looking path is not isolation proof. Use a reviewed runner that pins target/config and bounds resources/output; don't broadly allow Docker/SSH merely for convenience. Read-only logs may contain secrets: scope/redact them before returning.
When normal tool inputs cannot carry signed fields, .codex/hooks/invoke-authorized.ps1 accepts a request JSON through -RequestPath. It requires an externally supplied HARNESS_AUTHORITY_PUBLIC_KEY_XML trust root and a valid exact-command grant; the Agent must never create/replace that trust root or sign its own production grant. Request fields: command, cwd, harness_target, harness_version, harness_authorization (Payload/Signature). Do not include secrets. Default only validates; -Execute validates the inner command through the same Hook and then executes the signed PowerShell command in its bound cwd. Use only within concrete existing authority. A mutable runner/artifact must be pinned and checked by the signed command itself.
The signer/operator owns short windows, revocation/replay controls and target serialization; this adapter is not that service. No service or real key is installed by Harness migration. Without a real trusted grant/integration, report protected execution unavailable early, continue preparation, and request the smallest operator action ONCE. Repeated Human GO cannot fix a missing adapter. Never disable a guard or treat JSON approved fields as permission.
