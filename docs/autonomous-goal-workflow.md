# Continuous delivery, optional Goal state
A clear implementation request authorizes bounded local understanding -> implementation -> relevant verification -> repair/review -> accepted delivery without repeated GO. Analysis stays read-only. Ask only for consequential unresolved business decisions, missing authority, explicit budget exhaustion or no safe useful next step; complete independent preparation first.
Use platform Goal mode only on explicit request and follow its status/budget rules. Optional local goal-state.ps1 is continuity/scope defense, not a second authority issuer or mandatory task setup. S1 and clear small S2 need no Goal file/Packet.
For long work maintain one contract/capsule and visible milestones. Contract hash/range integrity remains mandatory. Progress capsule damage alone does not invalidate intact scope: reconstruct from local evidence and Checkpoint with next epoch; do not rewrite contract/authorization state. Validate/Close require coherent repaired progress and honest completion evidence. A missing grant cannot be repaired by a state flag.
Use risk-proportional repair time/cost estimates, not a universal retry count. Git network retries follow git-network-policy.md; a stalled push doesn't block valid local work. Broader repairs continue only with changed evidence and bounded cost. Required independent review is assigned early and checks final integrated changes. Production still needs target/version/window/check/rollback authority through a verified transport.
