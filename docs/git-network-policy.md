# Git baseline and network resilience
Project source-authority and explicit Git/delivery contracts take precedence. At task start confirm the required remote base and freeze its exact commit. Reuse it during development; on resume check local branch/HEAD/dirty files and relevant evidence. A compaction or stage label alone does not require ls-remote/fetch.
Recheck remote at integration, push conflict or delivery boundaries where required. Inspect incoming changes and rerun impacted checks; don't discard local work or pretend a stale initial base is current. If the FIRST required remote base cannot be established, do only work permitted by the project contract (at least read-only diagnosis); offline-start changes require applicable Human authorization.
For a network failure, allow one evidence-backed retry with a provisional 60-120 second total network budget. This is a tuning default, not a platform Goal status rule. Stop unchanged retries after it; mark only dependent steps blocked. With a valid established base, continue authorized local implementation, checks, review and commits; report push pending. Retry when connectivity changes or the blocked delivery boundary is reached, not after each local check.
Do not globally toggle proxy/TLS settings, disable certificate verification, loop between network backends or claim push/merge/release completion without evidence. Network diagnosis is code-audit-fix work, not a reason to edit business logic. Record command time separately from actual blocked wall time; no double-counting of overlap.
