# Cost-aware autonomous delivery

Optimize cost per accepted task and elapsed time to a verified outcome, not token count alone. The user prefers less Human participation, but not a large cost increase for marginal time savings. Quality, authorization and mandatory acceptance are non-negotiable floors. These controls do not add another Skill or require a separate Human approval for routine work.

## Before and during work
- Root remains the selected owner, not necessarily the author of every line. Use the cheapest demonstrated-suitable capability for bounded repetitive work; expensive reasoning belongs to genuine ambiguity, critical diagnosis and integration decisions. Do not change provider/root model silently.
- S1 defaults to root-direct with focused checks. S2 delegates only when the expected saved critical-path time, reduced root context/recovery burden, or useful independent evidence outweighs context duplication and integration. S3/S4 keep required independent review, but limit it to the changed boundary and relevant raw evidence rather than repeated whole-repository audits.
- Four threads is capacity, not a starting topology. Start only useful disjoint work. Prefer short task packets and relevant files over full-history forks; reuse a worker while its context remains relevant and close it when done. Do not pay a reviewer merely to restate root conclusions.
- Agent chooses a provisional risk-proportional time/token repair envelope from similar measured tasks, if any, and records it inline or in the existing Packet. This is a planning estimate, not an invented user spending permission or a platform budget setting. Honor explicit user/provider limits. When uncertainty is high, run one cheapest discriminating experiment before broader analysis.
- At a milestone or changed diagnosis, examine actual progress versus budget. Stop duplicate reading, unchanged retries, repeated whole-suite runs and gratuitous new agents. Narrow context, reuse deterministic evidence, or use an available cheaper bounded role. Do not downgrade mandatory tests or review to meet cost targets. If safe completion no longer fits explicit limits, report the smallest decision needed.
- Do not run paid A/B experiments, invoke additional providers, or schedule monitors without authorization. Routine authorized task usage may be observed passively.

## Agent-maintained evidence, no Human spreadsheet
Append a compact record to the existing completion evidence when usage is exposed: task ID, risk/type, acceptance/defects, start/end wall time, Human intervention count (excluding initial brief), repair effort, root/child usage coverage, provider/model metadata source, input/cached/output tokens and actual billed amount/currency if available. Token totals across models are not a price. Cached tokens must not be double-counted. Provider/token-assistant billing and cache multipliers take precedence over public list prices. Do not read auth files to obtain usage.

Use unavailable for inaccessible metrics. Platform Goal token accounting is not necessarily billable API usage and may omit/add overhead; do not convert it into money. Offline fixture tests make no model calls but the agent designing/running them still consumes tokens. A one-off Harness upgrade is not a representative daily-task cost baseline.

## Comparison and adjustment
Use comparable task classes, difficulty, acceptance and starting state; compare all attempts including failures/rework, sum all root/child cost and measure wall-clock elapsed time rather than adding parallel durations. Observe normal authorized work first; an old/new controlled replay needs its own authorization and isolated worktrees, never duplicate production deployment.

Initial tuning signal (not a proven universal cutoff): for comparable accepted-task samples, if billed cost rises over 25% but median elapsed time falls less than 15%, with no demonstrated quality/risk or Human-intervention improvement, simplify the route. Start by removing redundant agents, over-wide context and repeated QA, not useful Skills or safety boundaries. If money is unavailable, mark token growth only as a proxy and leave the economic verdict unmeasured. Fewer than five comparable tasks per route is preliminary evidence; do not announce causal productivity gains from it. Agent may recommend a route adjustment, but does not auto-migrate the Harness or add a model-upgrade Skill.

For optional analysis of already-collected records use scripts/evaluate-efficiency.py. Each task_id appears once per route; retries and children are aggregated inside that whole-task record. Duplicate IDs are rejected, and absent IDs keep evidence preliminary regardless of row count. Its wall_ratio uses total whole-task seconds including failed tasks divided by accepted outcomes; this is a task-time burden, not parallel batch makespan. The successful-only median is separately labeled and must not be marketed as overall speedup when failures increase. The review signal uses the failure-inclusive measure conservatively; assess actual accepted latency and quality alongside it. Its fixture tests validate arithmetic/missing-data handling, not real model economics.

## Passive diagnostic fields
Optional whole-task fields: compaction_count, compaction_seconds, git_retry_count, external_blocked_seconds, child_count, rework_seconds. evaluate-efficiency.py reports observed coverage and means only when complete. Child count is not a savings metric. Compaction/Git/background durations may overlap: do not add them into elapsed time or subtract them as proven net waste. No per-turn transcript scans, extra status agents or private billing/auth reads. Inaccessible data stays null. Compare routine same-class tasks, not a Harness upgrade against a small UI fix.
